## 1. Symptom

TEST på `http://<target-ip>:8080/remote` gav altid:

```
Last server status: Connection failed - Test shot sent
```

"Connection failed" betyder `http_post_last_status = -1`, dvs. `esp_http_client_perform()` fejlede
(`main/TCPIP/http_client.c`, `http_post_task()`). "Test shot sent" er kun beskeden om, at knappen blev trykket.

Med `{"TRACE":16}` (`DLT_COMMUNICATION`) på USB-konsollen:

```
C (43.216) POST https://markering.ou-taa.dk/api/skydninger {"shot":0, "test":1}
E (50987) esp-tls: [sock=62] select() timeout
E (50997) esp-tls: Failed to open new connection
E (50997) transport_base: Failed to open a new connection
E (50997) HTTP_CLIENT: Connection failed, sock < 0
```

DNS virkede (ellers `couldn't get hostname`), men TCP-forbindelsen blev aldrig etableret.

## 2. Fejlsøgning – hvad blev udelukket

| Tjek | Resultat |
|---|---|

| IPv6 | `markering.ou-taa.dk` har ingen AAAA-post |
| Statisk IP på target | `WIFI_IP` og `WIFI_GATEWAY` tomme → DHCP |
| Target'ens netværk | `192.168.1.119`, MAC `c0:4e:30:22:7b:c0` (Espressif), samme LAN som PC'en (`192.168.1.70`) |

## 4. Årsag: egen kopi af lwIP's socket-lag

`main/drivers/sockets.c` er en gammel kopi af lwIP's `sockets.c` (`lwip_socket()`, `lwip_connect()`,
`lwip_select()` …). `main/CMakeLists.txt` bygger alle filer under `main/` med `GLOB_RECURSE`, så kopien blev
linket ind og erstattede ESP-IDF's version. Bekræftet i `build_local/freeETarget.map`:

```
.text.lwip_connect  0x42016abc  0x10a  esp-idf/main/libmain.a(sockets.c.obj)
```

Kopien passer ikke til lwIP-headerne i ESP-IDF v5.3.5, og udgående forbindelser blev sendt til en forkert port.
Den præcise mekanisme blev ikke fundet (makroerne for port-konvertering er identiske med ESP-IDF's), men
fejlen forsvandt, så snart filen blev taget ud af bygget.

## 5. Følgefejl: port 8080-serveren startede ikke

Uden den gamle `sockets.c` fejlede den anden webserver ved opstart:

```
I (10.905) start_webserver(port: 8080)
E (13615) httpd: httpd_server_init: error in creating ctrl socket (112)
E (10.916) Error starting server!
```

112 = `EADDRINUSE`. Begge servere (port 80 og 8080) brugte standard-kontrolporten
`ESP_HTTPD_DEF_CTRL_PORT` (32768). Den gamle socket-kopi opdagede ikke konflikten.

## 7. Realistisk testskud

Det gamle testskud `{"shot":0, "test":1}` blev afvist af serveren med **HTTP 400**.
TEST bygger nu et `shot_record_t` og sender det gennem `build_json_score(&test_shot, SCORE_TCPIP)` – samme felter
som et rigtigt skud:

- `shot` = 1
- `session_type` = `SESSION_VALID | json_session_type`
- `time` = `run_time_ms()`
- `x`/`y` = tilfældigt punkt inden for ±5 mm af centrum

Eksempel (nøglen sendes som `X-API-KEY`-header og står derfor ikke i body):

```json
{"shot":1, "session_type":1, "time":17138, "time_to_go":368, "x":2.01, "y":2.83, "athelete":"", "event":"", "target_name":""}
```

Serveren svarer **HTTP 201** og gemmer testskuddet som et almindeligt skud.

## 9. Byg og flash uden ESP-IDF-terminal

`export.ps1` satte ikke `idf.py` på PATH i en almindelig PowerShell. Det virker at sætte miljøet manuelt:

```powershell
$env:IDF_PATH='C:\Espressif\frameworks\esp-idf-v5.3.5'; $env:IDF_TOOLS_PATH='C:\Espressif'
$py='C:\Espressif\python_env\idf5.3_py3.11_env\Scripts\python.exe'
foreach ($l in (& $py "$env:IDF_PATH\tools\idf_tools.py" export --format key-value)) {
  $k,$v = $l -split '=',2
  if ($k -eq 'PATH') { $v = $v -replace '%PATH%',$env:PATH -replace '\$PATH',$env:PATH }
  Set-Item "env:$k" $v
}
& $py "$env:IDF_PATH\tools\idf.py" -B build_local -p COM4 flash
```

Advarslen om manglende `idf_version.txt` kan ignoreres. Flash fejler med "Adgang nægtet", hvis en seriel monitor
har COM4 åben.
